# 安全、兼容性与事实边界

## 登录材料

新版不创建旧版 `tmp_raw.json`、`cookies_raw.json`、`cookies.json` 或 `_nes_cookies` 整库副本。现有的旧版文件不会因此消失，也不会被脚本自动扫描或清理。用户确认范围后，可以删除明确不再使用的副本；不要递归清理浏览器原始配置目录。若怀疑登录凭据已经外传，应从账号侧注销相关登录态。

已有未锁定副本在技术上仍可作为输入，但不建议为低频导出新增凭据缓存。没有经确认可用的副本且活动原库被锁时，抓取前须自行完全退出 Edge/Chrome；程序不强杀浏览器。若另外治理旧副本，不能仅从旧库 DELETE 其他行就宣称清干净，因为旧数据可能仍留在空闲页，见 [SQLite 官方说明](https://www.sqlite.org/lang_vacuum.html)。只留网易域名也不够，还需限定必要 Cookie 名、路径和有效期。复制原 Local State 仍保留原 profile 的密钥材料。本工具不自动复制、迁移或清理用户已有凭据文件。

密钥通过进程内存和受控子进程管道短暂存在；这减少落盘，不保证抵御管理员、恶意本机进程、交换文件或崩溃转储。聊天 JSON/TXT、图片、清单和备份仍为明文私密数据。POSIX 新写文件采用受限模式，Windows 继承输出目录 ACL；本工具不擅自修改用户现有目录的访问权限。

直接模式只选择 `music.163.com`、`.music.163.com`、`.163.com` 下的 MUSIC_U 和 __csrf，根域 Cookie 仅因其适用于音乐子域而保留；不同作用域出现同名不同值时拒绝，避免猜测登录身份。仅使用根路径、未过期、未分区记录。若实际站点以后需要不同字段或路径，应确认后修改，不能直接放开全部 Cookie。

v10 AES-GCM 按数据库版本处理域名绑定：Chromium 数据库 v24 增加 SHA256(host_key) 前缀，需验证再去除。依据 [Chromium 源码（版本 131）](https://chromium.googlesource.com/chromium/src/+/refs/tags/131.0.6761.0/net/extras/sqlite/sqlite_persistent_cookie_store.cc)。v20 不受支持，不尝试提权或反窃取绕过。支持该格式不等于每个浏览器配置均可读取。

## 接口与完整性

接口路径保留原项目方案：`/weapi/msg/private/users` 与 `/weapi/msg/private/history`。原实现中的协议固定参数不是账号凭据。2026-09-22 已在 Windows、Python 3.12.9、Node.js 24.15.0 的直接读取模式下，以真实账号完成列表、身份核对、分页抓取至 more=false、导出和重复追加验收，并独立验证了真实图片下载。该结论仅覆盖当次账号和环境；其他平台、浏览器兜底模式、未来接口变化和其他账号限流情况仍需单独验证。

用户列表使用 offset 分页；返回 `more=false` 时结束。对于缺少 more 的旧式响应，仅短于请求页长时结束用户列表；历史消息不使用这项假设，必须显式 more=false。找不到指定会话、双方身份冲突、未知发送者会停止，不根据模糊昵称猜测身份。

历史消息以最早时间向前翻页，按 ID 去重。若游标不能继续推进，保存部分结果，不通过减一跳过可能同毫秒的记录。不安全的 JavaScript 数字 ID 被拒绝，避免精度丢失后静默合并；字符串 ID 保持完整。页数上限 400，HTTP 超时 20 秒，最多三次请求尝试。分页完成不说明服务端仍保有全部历史。

未知发送者、接收人不符、消息冲突、非法 ID/时间戳属于硬失败：退出码 1 且不发布本次正文。网络失败、游标停滞或分页上限仍是部分结果：退出码 2，独立保存带停止原因的数据。

同一会话追加会保留旧记录。这意味着已经从服务端消失的旧消息仍可能留在本地备份；本工具不是删除同步器。引用直接 ID 匹配才确认；减一仅标候选。未解析、未下载、未识别类型都不能被叙述成已确认事实。

每个文件单独原子替换并保留备份，不能保证 JSON/TXT/清单之间跨文件同时提交。JSON 为权威记录；若中断导致 TXT 没有同步，重新执行导出刷新。备份不会自动轮换清理，应由用户选择保留周期。

## 图片

只允许 p数字.music.126.net 和 p数字c.music.126.net 的 HTTPS 公网地址；这是保守默认集合，不宣称覆盖全部网易图片 CDN。DNS 返回的所有地址必须为公网，再把连接固定到检查过的数值 IP，同时保留原主机名进行 TLS 证书校验；系统代理不会被此下载器使用。每次重定向重新验证，上限三跳，单图最多 20 MiB。

白名单域名的历史 HTTP 默认端口链接会先在本地升级为 HTTPS，再做 DNS/TLS 访问；原 JSON 的 picUrl 保留用于追溯。重定向同样升级并验证，不降级连接。响应头仅作允许图片类型粗筛；CDN 可能把 PNG 标为 `image/jpg`，因此不要求响应头与文件签名一致。实际文件签名必须属于支持格式，保存扩展名按签名决定，不能仅凭响应头通过检查。

检查 Content-Type 和 JPEG/PNG/GIF/WebP 文件签名，可挡掉常见 HTML 错页，但不等于完整图像解码或恶意文件扫描。图片本身及链接可能包含隐私；清单不再重复远程 URL，但消息 JSON 仍保留 picUrl 以支持追溯。图片发起请求会向对应 CDN 暴露客户端 IP 等常规网络信息，不发送账号 Cookie。

## 一起听与历史经验

保留 type=23 为“一起听邀请”。如果 raw.generalMsg.nativeUrl 确有房间 ID 和时间字段，可以解释为邀请/房间创建线索，不能据此断定用户实际加入、听完、听了哪首歌或说过什么。原项目关于本地数据库为空、全部聊天室接口不可用、固定返回数量等内容是旧环境经验，不再作为长期保证；本修复未重新验证这些远端结论，也未增加账号探测或其他用户排行采集。

## 发布与扫描

源码、文档、测试采用固定发布白名单；二进制、导出、改名文件、Cookie 数据库和额外目录都不能直接打包。`.git` 与 `__pycache__` 不检查内容且永不打包，扫描会提示。内容规则检查明显凭据字面值、明文密钥、个人路径、手机号形态和可配置敏感词；无法自动识别所有昵称、关系描述或经过编码的隐私。

不要把扫描通过当作安全认证，也不要用 `.gitignore` 判断 ZIP 是否安全。打包后还应核对清单。用户明确要求发布之前，只生成本地文件，不发送到外部服务。
